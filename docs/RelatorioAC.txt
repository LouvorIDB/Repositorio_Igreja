# 1. ARQUITETURA

O sistema é baseado no **Google Apps Script (V8 Runtime)** executado na infraestrutura serverless da nuvem Google e vinculado a uma planilha do **Google Sheets**, que funciona como camada de persistência e banco de dados relacional.

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│                                FRONTEND EXTERNO                                 │
│                       (Site Web / App da Equipe de Louvor)                      │
└───────────────────────────────┬──────────────────▲───────────────────────────────┘
                                │ (HTTP POST JSON) │ (HTTP GET JSON)
                                ▼                  │
┌──────────────────────────────────────────────────────────────────────────────────┐
│                               GOOGLE APPS SCRIPT                                 │
│                                 (V8 Runtime)                                     │
│                                                                                  │
│   ┌────────────────────────┐                   ┌─────────────────────────────┐   
│   │        doGet()         │                   │          doPost()           │   
│   └───────────┬────────────┘                   └──────────────┬──────────────┘   
│               │                                               │                  
│               └───────────────────────┬───────────────────────┘                  
│                                       ▼                                          
│                        ┌──────────────────────────────┐                          
│                        │      SpreadsheetApp API      │                          
│                        └──────────────┬───────────────┘                          
└───────────────────────────────────────┼──────────────────────────────────────────┘
                                        │
                                        ▼
┌──────────────────────────────────────────────────────────────────────────────────┐
│                                 GOOGLE SHEETS                                    │
│  [Playlists]   [Banco_Musicas]   [Cantores]   [Musicas_Novas]   [Solicitacoes]    │
└──────────────────────────────────────────────────────────────────────────────────┘
```

### Relação entre os Componentes:

* **Google Sheets:** Atua como o banco de dados do sistema. As abas (`Playlists`, `Banco_Musicas`, `Cantores`, `Musicas_Novas`, `Historico`, `Solicitacoes`) armazenam as tabelas e dados operacionais.
* **Código.js:** Contém toda a lógica de servidor em JavaScript. Possui rotinas acionadas pela interface do editor (`onOpen`, `gerarBlocoCulto`, `processarEscolha`, `salvarNoHistorico`, `limparPlanilhaPrincipal`) e manipuladores de requisição HTTP (`doGet` e `doPost`).
* **PromptCulto.html:** Componente de interface gráfica (modal) aberto dentro do próprio Google Sheets. Comunica-se com o backend via `google.script.run`.
* **Endpoint `doGet`:** Interface de leitura exposta como Web App. Retorna o estado atual das tabelas em JSON para consumo do frontend externo.
* **Endpoint `doPost`:** Interface de escrita exposta como Web App. Recebe requisições HTTP POST com objetos JSON contendo a propriedade `acao` para criar, modificar ou ocultar dados na planilha.
* **Frontend Externo:** Aplicação cliente externa (Web/Mobile) que interage com os endpoints `doGet` e `doPost` para exibir e gerenciar a escala do ministério de louvor.

* **Dados Retornados:** Matrizes bidimensionais contendo os valores brutos de 4 abas principais da planilha.
* **Abas Consultadas:** `Playlists`, `Banco_Musicas`, `Cantores`, `Musicas_Novas`.
* **Estrutura do JSON Retornado:**
  ```json
  {
    "cultos": [
      ["15/08 - CULTO DE DOMINGO", "", "", "", "", "{\"violao\":\"João\"}", "Carlos, Ana"],
      ["Grande É o Senhor", "G", "Original", "https://...", "https://...", "", "Carlos"]
    ],
    "repertorio": [
      ["Nome da Música", "Tom", "Artista", "Link VS", "Link YT"]
    ],
    "banco": [
      ["Nome da Música", "Tom", "Artista", "Link VS", "Link YT"]
    ],
    "cantores": [
      ["Nome do Cantor"]
    ],
    "novas": [
      ["Nome da Música", "Tom", "Artista", "Link VS", "Link YT"]
    ]
  }
  ```
* **Nomes das Propriedades:** `cultos`, `repertorio`, `banco`, `cantores`, `novas`.
* **Tratamento de Erros:** Não há bloco `try...catch` global. Se alguma aba não for encontrada, o operador ternário atribui uma matriz vazia `[]` como fallback.

## 3.2. Endpoint `doPost`

### Ação 1: `moverMusicasNovas`
* **Nome da Ação:** `moverMusicasNovas`
* **Dados Esperados:** `{"acao": "moverMusicasNovas"}`
* **Validações:** Checa se a aba `Musicas_Novas` existe e se possui dados além do cabeçalho (`getLastRow() > 1`).
* **Abas Utilizadas:** `Musicas_Novas`, `Banco_Musicas`.
* **Operações Realizadas:**
  1. Lê as músicas sugeridas da aba `Musicas_Novas` (linhas 2 em diante).
  2. Escreve os registros no final da aba `Banco_Musicas`.
  3. Reordena a aba `Banco_Musicas` alfabeticamente pela Coluna A (ignorando o cabeçalho).
  4. Exclui as linhas processadas da aba `Musicas_Novas`.
* **Resposta Retornada:**
  * Se houver dados: `{"status": "sucesso"}`
  * Se estiver vazia: `{"status": "vazio"}`
* **Possíveis Erros:** Erros de concorrência ao tentar deletar linhas ou falha se a aba `Banco_Musicas` não existir.

---

### Ação 2: `toggleOculto`
* **Nome da Ação:** `toggleOculto`
* **Dados Esperados:** `{"acao": "toggleOculto", "startIndex": 10}`
* **Validações:** Converte o índice recebido adicionando 1 (`startIndex + 1`).
* **Abas Utilizadas:** `Playlists`.
* **Operações Realizadas:**
  1. Seleciona a célula A da linha correspondente (`startIndex + 1`).
  2. Executa Regex `/ - OCULTO/i`. Se contiver a string, remove-a; caso contrário, sufixa ` - OCULTO`.
  3. Atualiza o valor da célula na planilha.
* **Resposta Retornada:** `{"status": "sucesso", "novoValor": "15/08 - CULTO DE DOMINGO - OCULTO"}`
* **Possíveis Erros:** Passar um `startIndex` inválido ou fora dos limites da aba `Playlists`.

---

### Ação 3: `salvarCulto`
* **Nome da Ação:** `salvarCulto`
* **Dados Esperados:**
  ```json
  {
    "acao": "salvarCulto",
    "editandoIndex": null,
    "titulo": "15/08 - CULTO DE DOMINGO",
    "instrumentos": { "violao": "João", "teclado": "Maria" },
    "cantoresCulto": ["Carlos", "Ana"],
    "musicas": [
      {
        "nome": "Grande É o Senhor",
        "tom": "G",
        "variacao": "Original",
        "vs": "https://...",
        "yt": "https://...",
        "cantores": ["Carlos"]
      }
    ]
  }
  ```
* **Validações:** Verifica se `editandoIndex !== null` para definir se é uma atualização de bloco existente ou inserção de um novo culto.
* **Abas Utilizadas:** `Playlists`.
* **Operações Realizadas:**
  * **Modo Edição (`editandoIndex !== null`):**
    1. Calcula `startRow = editandoIndex + 1`.
    2. Varia as linhas para baixo contando a quantidade de linhas do bloco antigo até encontrar `"CULTO DE"` ou linha em branco.
    3. Deleta o bloco antigo com `deleteRows()`.
    4. Abre espaço para o novo bloco com `insertRowsBefore()`.
  * **Modo Criação (`editandoIndex === null`):**
    1. Define `startRow = getLastRow() + 2`.
    2. Insere as novas linhas no final da planilha com `insertRowsAfter()`.
  * **Gravação dos Dados:**
    1. Grava o título na linha de cabeçalho (A:E mesclados com fundo `#ea4335`).
    2. Serializa o objeto `instrumentos` em JSON na Coluna F.
    3. Grava os cantores do culto separados por vírgula na Coluna G.
    4. Grava cada música nas linhas subsequentes (Coluna A: Nome, B: Tom, C: Variação, D: VS, E: YT, F: Vazio, G: Cantores da música).
* **Resposta Retornada:** `{"status": "sucesso"}`
* **Possíveis Erros:** `editandoIndex` incorreto apontando para fora da planilha ou inconsistência na contagem de linhas do bloco antigo.

---

### Ação Fallback (Solicitações de Integrantes)
* **Nome da Ação:** Qualidade genérica / Fallback quando `acao` não é nenhuma das anteriores.
* **Dados Esperados:**
  ```json
  {
    "categoria": "Ajuste de Tom",
    "musica": "Agraço de Pai",
    "autor": "Pedro",
    "texto": "Solicito mudar tom para D"
  }
  ```
* **Validações:** Verifica se a aba `Solicitacoes` existe; se não existir, cria a aba e insere o cabeçalho `["Data/Hora", "Categoria", "Música / Culto", "Quem Pediu", "Solicitação"]`.
* **Abas Utilizadas:** `Solicitacoes`.
* **Operações Realizadas:** Anexa uma nova linha no final da aba com `appendRow()`.
* **Resposta Retornada:** `{"status": "sucesso"}`
* **Possíveis Erros:** Erros de permissão de criação de nova aba.

# 5. PLAYLISTS / CULTOS

### Como um Culto é Representado na Aba `Playlists`:

Um culto é um bloco estruturado de N+2 linhas na aba `Playlists`.

```
Linha Cabeçalho │ [ 15/08 - CULTO DE DOMINGO ] (A:E Mescladas) │ JSON_Inst (F) │ Cantores (G)
Linha Música 1  │ Nome (A) │ Tom (B) │ Var (C) │ VS (D) │ YT (E) │ (Vazio F) │ Cantores_Música (G)
Linha Música 2  │ Nome (A) │ Tom (B) │ Var (C) │ VS (D) │ YT (E) │ (Vazio F) │ Cantores_Música (G)
Linha Rodapé    │ [ Linha de Rodapé em Branco / Separador ] (A:G)
```

* **Cabeçalho:** A Coluna A contém o título (ex: `"15/08 - CULTO DE DOMINGO"`). As células de A a E são mescladas.
* **Instrumentos:** Armazenados no cabeçalho na **Coluna F** como string JSON (ex: `{"violao":"João","bateria":"Pedro"}`).
* **Cantores do Culto:** Armazenados no cabeçalho na **Coluna G** separados por vírgulas.
* **Músicas:** Armazenadas nas linhas imediatamente abaixo do cabeçalho. Cada música ocupa 1 linha da Coluna A à E. A Coluna G armazena os cantores específicos daquela canção.
* **Término do Culto:** O bloco termina em uma linha em branco ou no cabeçalho do culto seguinte.
* **Localização:** Localizado via `startIndex` / `editandoIndex` informado pelo frontend, convertido para a linha real da planilha (`index + 1`).
* **Substituição:** O algoritmo conta as linhas do bloco antigo varrendo a coluna A até encontrar a string `"CULTO DE"`, exclui as linhas antigas com `deleteRows()` e insere as novas com `insertRowsBefore()`.
* **Ocultação:** Ação `toggleOculto` altera o texto da Coluna A da linha de cabeçalho adicionando ou removendo o sufixo ` - OCULTO`.
* **Dependência da String `"CULTO DE"`:** Presente no `processarEscolha` (linha 49), `buscarProximaData` (linha 94) e `salvarCulto` (linha 252). Se essa string exata não for encontrada, o parser falhará ao delimitar o final do bloco.

* **Endpoints:**

# 8. SEGURANÇA

* **Autenticação:** Ausente. O arquivo `appsscript.json` especifica `"access": "ANYONE_ANONYMOUS"`.
* **Autorização:** Ausente. Qualquer usuário com a URL do Web App pode executar leituras ou mutações.
* **Validações:** Mínimas (apenas checa se a aba `Musicas_Novas` possui dados antes de mover).
* **Endpoints Públicos:** Tanto `doGet` quanto `doPost` são públicos.
* **Dados Sensíveis:** Nomes de membros do ministério de louvor e links internos de ensaios expostos.
* **Segredos:** Não há uso de chaves ou tokens secretos no código.
* **Operações Destrutivas Expostas:** Deletar linhas (`deleteRows()`) de cultos antigos e apagar a aba `Musicas_Novas`.
* **Riscos de Requisições Anônimas:** Acesso anônimo malicioso pode apagar o conteúdo da aba `Playlists` ou inundar a planilha com solicitações falsas.

# 12. PROBLEMAS

### 🔴 CRÍTICOS
1. **Função Faltante no Menu:** Chamada para `sincronizarArquivosDrive()` no menu `onOpen` lança erro ao ser acionada.
2. **Falta de Trava de Concorrência:** Ausência de `LockService` nas operações de escrita do `doPost`.

### 🟠 ALTOS
3. **Falta de Autenticação/Autorização:** Web App exposto como `ANYONE_ANONYMOUS` sem token de validação.
4. **Desalinhamento Visual do Cabeçalho:** `processarEscolha` e `salvarCulto` mesclam 5 colunas em um layout de 7 colunas.
5. **Vulnerabilidade no Parser por String:** Lógica de identificação dependente exclusivamente do texto `"CULTO DE"`.

### 🟡 MÉDIOS
6. **Ausência de `try/catch` no `doGet`:** Riscos de quebra de leitura com erro 500.
7. **Contagem de Linhas por Loop Frágil:** Algoritmo de limpeza de linhas vazias no modo edição suscetível a erros de formatação.

### 🟢 BAIXOS
8. **Mistura de Padrões de Nomenclatura:** Variáveis alternando entre inglês e português.
9. **Falta de Logs Estruturados:** Sem uso ativo de auditoria via `console.log`.

# 14. FLUXOS

### A) Usuário acessa o site
1. O usuário abre a página web no navegador.
2. O aplicativo solicita os dados do backend via requisição HTTP GET.

### B) Site carrega os dados
1. O backend recebe a requisição no `doGet()`.
2. O script consulta as abas `Playlists`, `Banco_Musicas`, `Cantores` e `Musicas_Novas`.
3. Retorna o JSON com todos os arrays de dados.
4. O frontend renderiza a interface na tela.

### C) Administrador entra
1. O administrador se autentica na interface do frontend cliente.

### D) Administrador cria um culto
1. O administrador envia os dados do culto via `POST` com `acao: "salvarCulto"` e `editandoIndex: null`.
2. O `doPost` localiza o final da aba `Playlists` (`getLastRow() + 2`).
3. Escreve o cabeçalho (com JSON de instrumentos e cantores) e as linhas de músicas.
4. Retorna `{"status": "sucesso"}`.

### E) Administrador edita um culto
1. O administrador edita um culto existente e envia um `POST` com `acao: "salvarCulto"` e `editandoIndex: N`.
2. O `doPost` calcula a linha inicial (`N + 1`), conta as linhas do bloco antigo varrendo até o próximo `"CULTO DE"`, exclui as linhas antigas e insere as novas.

### F) Administrador altera escala
1. O administrador altera integrantes nos campos de instrumentos ou cantores.
2. O fluxo segue o mesmo caminho da **Edição de Culto (Item E)**.

### G) Usuário envia solicitação
1. O integrante envia um pedido ou aviso pelo site.
2. O frontend envia `POST` com a estrutura de solicitação (fallback).
3. O backend garante a aba `Solicitacoes` e insere a linha com `appendRow()`.

### H) Músicas novas são movidas para o banco
1. O administrador aprova as músicas sugeridas no site.
2. O frontend envia `POST` com `acao: "moverMusicasNovas"`.
3. O `doPost` lê os dados de `Musicas_Novas`, anexa ao final de `Banco_Musicas`, reordena de A a Z e deleta o conteúdo de `Musicas_Novas`.

### I) Culto é ocultado
1. O administrador clica em ocultar/exibir um culto.
2. O frontend envia `POST` com `acao: "toggleOculto"` e `startIndex`.
3. O `doPost` seleciona a célula do cabeçalho na aba `Playlists` e insere ou remove a string ` - OCULTO`.

### J) Dados são registrados no histórico
1. O usuário seleciona um intervalo na planilha pelo Google Sheets.
2. Aciona o menu `⛪ Ministério` -> `Arquivar Seleção no Histórico`.
3. Informa o Mês/Ano no prompt.
4. O script copia o intervalo para o final da aba `Historico` e preenche a coluna H.

* **Resposta:**
  ```json
  {
    "cultos": [ ["String"] ],
    "repertorio": [ ["String"] ],
    "banco": [ ["String"] ],
    "cantores": [ ["String"] ],

  }
  ```

---

### POST `/exec` — `moverMusicasNovas`
* **Requisição:** `{"acao": "moverMusicasNovas"}`
* **Processamento:** Copia registros de `Musicas_Novas` para `Banco_Musicas`, ordena alfabeticamente e limpa a aba de origem.
* **Resposta:** `{"status": "sucesso"}` ou `{"status": "vazio"}`

---

### POST `/exec` — `toggleOculto`
* **Requisição:** `{"acao": "toggleOculto", "startIndex": 5}`
* **Processamento:** Altera o texto da célula A da linha `startIndex + 1` adicionando ou removendo ` - OCULTO`.
* **Resposta:** `{"status": "sucesso", "novoValor": "15/08 - CULTO DE DOMINGO - OCULTO"}`

---

### POST `/exec` — `salvarCulto`
* **Requisição:**
  ```json
  {
    "acao": "salvarCulto",
    "editandoIndex": null,
    "titulo": "15/08 - CULTO DE DOMINGO",
    "instrumentos": { "violao": "João" },
    "cantoresCulto": ["Ana"],
    "musicas": [
      {
        "nome": "Santo Espírito",
        "tom": "E",
        "variacao": "Original",
        "vs": "",
        "yt": "",
        "cantores": ["Ana"]
      }
    ]
  }
  ```
* **Processamento:** Exclui o bloco antigo (se em edição) ou insere um novo bloco no final de `Playlists`.
* **Resposta:** `{"status": "sucesso"}`

---

### POST `/exec` — Fallback (Solicitações)
* **Requisição:**
  ```json
  {
    "categoria": "Observação",
    "musica": "Santo Espírito",
    "autor": "Gabriel",
    "texto": "Aumentar a introdução"
  }
  ```
* **Processamento:** Anexa uma linha com os dados da solicitação na aba `Solicitacoes`.
* **Resposta:** `{"status": "sucesso"}`

# RESUMO EXECUTIVO

Este sistema funciona como uma ponte automatizada entre uma planilha do **Google Sheets** (que atua como banco de dados) e uma **aplicação web externa** utilizada pelo ministério de louvor da igreja.

1. **Operação Interna:** Na planilha, os voluntários utilizam menus personalizados para gerar rapidamente tabelas formatadas de cultos (Domingo, Quarta ou Sábado), arquivar seleções no histórico e limpar dados antigos.
2. **Operação Externa (API):** O script disponibiliza uma API HTTP pública. Quando o site/aplicativo web é aberto, ele chama a função `doGet` para carregar a lista de cultos, o repertório de músicas e os cantores. Quando um administrador cria, altera ou oculta um culto no site, o aplicativo envia um `POST` para a função `doPost`, que altera, insere ou remove diretamente as linhas e cores dentro da planilha do Google Sheets.
